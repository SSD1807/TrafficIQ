# Feature-status report — v3 final (2026-11-10)

**Plain-language summary:** the application is a *synthetic-data* traffic prediction and routing demonstrator. It is **not** a live Bhubaneswar
traffic system. Live data would only be involved if (a) real OpenStreetMap roads are downloaded (static geometry, not traffic) and (b) a TomTom
key is configured **and** a route result reports `traffic_flow.status == "applied"`. Neither could be exercised against the real services in the
build environment (no internet, no keys).

Status vocabulary — **VERIFIED**: executed and checked here. **MOCK-VERIFIED**: logic executed end-to-end, but external HTTP replaced by a local
mock. **UNVERIFIED**: implemented, never run against the real thing. **NOT DONE**.

## Real defects found only by running the dashboard in a browser (all fixed)
1. Confidence columns displayed `1%` for 90 % (format string did not scale 0–1 values).
2. One-way arrow plugin threw under the canvas renderer and aborted the whole map script on any real one-way data — would have blanked the map on the real OSM graph. Replaced with rotated marker arrows; regression tests added.
3. Plotly legends overlapped axis titles; hover toolbar overlapped chart titles.
4. Route-planner legend colours contradicted the drawn route colours; legend dominated the small map.
5. A form wrapper froze the picker widgets (found earlier by AppTest) and the Copilot's suggested prompt was not understood by the rule-based engine.
6. Prediction table was clipped; weather card showed "none".

## Limits to state honestly in the report/viva
* Everything the models learned and every metric comes from **synthetic** data (2023-03-14 replay). Location→coordinate placement is approximate.
* "Simulated congestion" road colouring is a deterministic scenario model, not measured traffic.
* Test counts: **61 tests, 0 warnings, 0 failures** (v2 had 28).
